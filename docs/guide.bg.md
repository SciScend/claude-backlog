# claude-backlog - ръководство за потребителя

Това ръководство обяснява какво прави claude-backlog, как се инсталира, как
се добавят задачи, какво се случва, докато не си пред компютъра, и как се
преглежда резултатът. Предполага се, че знаеш какво е терминал, git и
браузър, но не познаваш вътрешността на проекта.

Техническите термини (worktree, branch, queue, prompt, commit, diff, merge,
service, systemd, hook, usage limit и т.н.) са оставени на английски. Имената
на командите, настройките, колоните и бутоните на дъската също са както в
интерфейса.

## 1. Какво е claude-backlog

claude-backlog е "backlog" (списък със задачи) за Claude Code. Идеята е
проста: когато имаш дълга работа, която Claude може да свърши сам (миграция,
рефакториране, писане на тестове, обновяване на документация), не стоиш пред
компютъра да я гледаш. Описваш задачата веднъж, оставяш я в опашка, и Claude
я изпълнява, докато те няма. На сутринта (или след обяда) намираш готов
резултат в отделен git branch, който преглеждаш като обикновен diff и
сливаш, ако ти харесва.

Какво получаваш:

- **Дъска в браузъра**, която работи на твоя компютър: виждаш какво чака,
  какво тече и какво е готово.
- **Изпълнение, докато те няма.** Натискаш **Run now** преди да тръгнеш или
  просто се отдалечаваш: когато screensaver-ът е включен достатъчно дълго,
  опашката тръгва сама, а когато се върнеш, спира.
- **Ограничение на седмичното ползване.** Приложението спира да започва нови
  сесии, когато седмичното ти ползване достигне зададен дял (по подразбиране
  50%), за да остане и за теб.
- **Една задача наведнъж, всяка в свой branch.** Работният ти екземпляр на
  проекта не се пипа. Всяка задача работи в отделен git worktree на branch
  `backlog/<task>`.
- **Изчакване на 5-часовите лимити**, без твоя намеса.
- **Лесно добавяне на задачи** - през `/backlog` в Claude Code, през формата
  на дъската или през командния ред.

### Отношението към claude-nightshift

claude-backlog не е самостоятелен "двигател". Той работи заедно с втори
инструмент, [claude-nightshift](https://github.com/SciScend/claude-nightshift),
като двата си поделят задачите ясно:

| Инструмент | Какво прави |
|---|---|
| claude-nightshift | Изпълнява **една** задача през няколко 5-часови usage windows, в рамките на седмичен бюджет. Когато спре, казва защо - чрез exit code. |
| claude-backlog | Всичко около него: опашката, дъската, стартирането и спирането (Run now, откриване на отсъствие), git worktrees, `systemd-inhibit`, конвенциите за задачите и отчетите. |

Защо е така? Следенето на usage limit-ите е трудна и променлива част; тя е
на едно място (nightshift). claude-backlog никога сам не решава нищо по
цифрите за ползването - той просто стартира nightshift и реагира на exit
code-а му. Ако искаш друго поведение на лимитите, то се променя в
nightshift, не тук.

claude-nightshift се инсталира автоматично заедно с claude-backlog.

> Забележка: claude-backlog е независим open-source инструмент. Не е
> създаден и не е одобрен от Anthropic. Той стартира Claude Code с твоя
> собствен login и абонамент.

## 2. Как работи накратко

Пътят на една задача от идеята до резултата:

```
 1. ДОБАВЯНЕ            /backlog, форма "New task" или `claude-backlog add`
        |
        v
 2. PROMPT              кратко описание -> Claude пише пълен prompt
        |               (status "drafting"), с въпроси и предположения
        v
 3. QUEUE               задачата чака в High / Normal / Low
        |
        v
 4. СТАРТ               Run now  ИЛИ  screensaver-ът е включен 15 минути
        |
        v
 5. ИЗПЪЛНЕНИЕ          нов git worktree + branch backlog/<task>;
        |               claude-nightshift пуска Claude; бележки в STATE.md;
        |               при 5-часов лимит - изчаква и продължава
        v
 6. КРАЙ НА ОПИТА       Claude пише SUMMARY.md  ->  колона Done
        |               без успех -> обратно в queue (до 3 опита)
        |               или Needs attention
        v
 7. ПРЕГЛЕД             четеш SUMMARY.md, commits и diff на дъската
        |
        v
 8. MERGE               git merge backlog/<task>  (или се отказваш)
```

Важни неща, които е добре да знаеш от самото начало:

- Задачата **започва от последния commit**. Промени, които още не са
  commit-нати във твоя екземпляр, не са част от нея.
- Claude работи **без да пита** - никой не е там да отговаря. Затова
  prompt-ът трябва да е самодостатъчен (виж [раздел 5](#5-добавяне-на-задачи)).
- Нищо не се слива и не се изпраща (push) без теб. Merge-ът е твое решение.

## 3. Инсталация и изисквания

### Изисквания

- Linux със systemd (user services).
- [Claude Code](https://docs.claude.com/en/docs/claude-code), инсталиран и
  с влезли (logged in) потребител.
- git и Python 3.10 или по-нов, и [uv](https://docs.astral.sh/uv/) (или
  pipx).
- За достъп от телефон: [Tailscale](https://tailscale.com) на компютъра и
  на телефона.
- По избор: git 2.38 или по-нов - с него дъската проверява за merge
  конфликти (чрез `git merge-tree`).

### Инсталиране

```bash
uv tool install git+https://github.com/SciScend/claude-backlog
claude-backlog install
```

Командата `install` прави следното:

| Какво | Къде / как |
|---|---|
| systemd user service | `~/.config/systemd/user/claude-backlog.service`; пуска дъската на <http://127.0.0.1:8765/> |
| Skill за Claude Code | `~/.claude/skills/backlog/SKILL.md` - дава командата `/backlog` |
| Launcher | "Claude Backlog" в менюто на десктопа (`claude-backlog.desktop`) |

Ако `claude` не е в PATH, `install` те предупреждава. Ако в
`~/.claude/skills/backlog/` вече има чужд файл със същото име, той не се
презаписва.

Service-ът се стартира веднага (`systemctl --user enable --now`). Отваряш
дъската с:

```bash
claude-backlog open
```

или от launcher-а в менюто.

### Защо е важно linger

User service-ът на systemd по принцип спира, когато излезеш от системата
(log out). Ако искаш дъската и опашката да работят и тогава, трябва да е
включен "linger":

```bash
loginctl enable-linger
```

`install` проверява това и ако linger е изключен, ти го съобщава.
(Забележи, че при заключен екран/screensaver ти не си излязъл от системата,
така че обичайният сценарий "отивам си за през нощта със заключен екран"
работи и без linger. Linger е нужен, ако се разлогваш.)

### Други подкоманди за управление

```bash
claude-backlog uninstall       # маха service-а, skill-а и launcher-а; задачите остават
claude-backlog serve           # пуска service-а на преден план (за опити)
claude-backlog serve --port N  # на друг порт
claude-backlog --help          # всички команди
```

Портът по подразбиране е 8765 (настройката `port`); телефонният порт е
следващият (8766). За да изпробваш приложението без инсталиране, виж
раздела "Development" в README.

### Къде са данните

- Данни: `~/.local/share/claude-backlog/` (или папката в
  `$CLAUDE_BACKLOG_HOME`): базата, папките на задачите
  (`tasks/<id>/` с prompt, `STATE.md`, `SUMMARY.md` и логове), worktrees и
  отчетите (`reports/`).
- Service: `~/.config/systemd/user/claude-backlog.service`; логове с
  `journalctl --user -u claude-backlog`.
- `$CLAUDE_BACKLOG_NIGHTSHIFT` променя начина, по който се стартира
  claude-nightshift.

## 4. Дъската

Дъската е уеб страница на твоя компютър (по подразбиране
<http://127.0.0.1:8765/>). Не е достъпна от мрежата - слуша само на
`127.0.0.1`.

![Дъската: задачи on hold, queue в три приоритетни групи, running задача и готови или такива, които се нуждаят от внимание](images/board.png)

### Колони

| Колона | Какво съдържа |
|---|---|
| **On hold** | Задачи, които не се изпълняват. Тук отиват и чернови, които чакат твой отговор на блокиращ въпрос, и такива, при които писането на prompt-а се е провалило. |
| **Queue** | Задачи, готови за изпълнение, в три групи по приоритет: **High**, **Normal**, **Low**. Изпълняват се отгоре надолу: първо High, после Normal, после Low. |
| **Running** | Задачата, която се изпълнява в момента (винаги най-много една). |
| **Done** | Завършените задачи. Докато не ги отвориш, са означени с "new". |
| **Needs attention** | Задачи, които не са успели или не са се побрали в позволените опити. Картата казва причината. |

Освен това има временно състояние "drafting" (Claude пише prompt-а) - такава
задача се вижда на дъската веднага, но още не може да се изпълни.
Архивираните задачи (Archived) не се показват, освен с
`claude-backlog list -a`.

### Горната лента

- **New task** - отваря формата за нова задача.
- **Run now** - стартира опашката веднага. Малкото меню до него ("Run until
  a time") започва изпълнение, което не взема нови задачи след зададен час
  ("Start no new task after" / "Run until then").
- **Stop after this task** и **Stop now** - виж [раздел 6](#6-изпълнение).
- **Settings** - настройките.
- Превключвател **Start when I am away** - дали опашката да тръгва сама,
  когато те няма.
- Лента за ползването (usage) с маркер за седмичния лимит: кликването върху
  маркера променя къде спира опашката.

### Карти и drag and drop

Всяка задача е карта със заглавие, проект и кратки означения (брой commits,
"new", "merged", предупреждения за конфликти и т.н.).

- **Drag and drop** променя реда и приоритета: влачиш карта в друга група
  (High / Normal / Low), нагоре или надолу. Така можеш да местиш и между
  колони: On hold <-> Queue, а от Done или Needs attention обратно към
  Queue (това е същото като бутона **Run again**).
- Докато влачиш, целта, на която ще падне картата, се оцветява.
- Бутонът **Run next** на картата (в панела на задачата) я слага най-отпред
  в опашката.
- Задачите в **On hold** не се изпълняват никога, докато не ги преместиш.

### Прозорец (панел) на задачата

Клик върху карта отваря панел със следните табове:

| Таб | Какво показва |
|---|---|
| **Overview** | Статус, приоритет, проект, зависимост ("Starts after ..."), опитите (всеки със свой лог), `SUMMARY.md` на Claude, commits на branch-а, предупреждения за конфликти, команда за merge. Тук са и действията: **Run next**, **Put on hold**, **Add to the queue**, **Run again**, **Archive**, **Delete** и **Delete the branch**. |
| **Prompt and settings** | Prompt-ът (можеш да го четеш и променяш, докато задачата не работи), заглавието, моделът, effort, брой прозорци и опити за тази задача. Някои полета (проект, base branch, "Start after") се заключват, щом задачата е започнала, защото от тях зависи нейният branch. |
| **Log** | Логът на опита - следи се на живо, докато задачата тече. |
| **Changes** | Diff-ът на branch-а спрямо началната му точка. |

Няколко действия, които лесно се бъркат:

- **Archive** маха worktree-то, но **запазва branch-а**.
- **Delete** изтрива задачата и историята ѝ, но също запазва branch-а.
- **Delete the branch** изтрива branch-а и worktree-то. Неслетите commits
  се губят, затова дъската пита за потвърждение.

### На телефон

Колоните стават табове (Queue, Running, Done, On hold), а всяка карта има
бутони **Top**, **Up**, **Down** и **Hold**.

## 5. Добавяне на задачи

Prompt-ът е всичко, което следващата Claude сесия ще знае. Никой няма да е
там да отговаря на въпроси, затова го пиши за човек, който не може да те
попита нищо: каква е целта, кои файлове са замесени, как се проверява
резултатът и кога е готово.

Има три начина.

### 5.1. `/backlog` в Claude Code

Докато работиш с Claude в някой проект и видиш, че идва дълга работа,
напиши `/backlog` (по желание с подсказка, напр. `/backlog миграция на
API клиента`). Skill-ът:

1. определя задачата (от аргумента или от последния разговор) и папката на
   проекта (git root-ът на текущата директория);
2. проверява за **некомитнати промени** (`git status --porcelain`) и за
   други задачи на същия repository, които още не са слети
   (`claude-backlog list -C <папка>`);
3. чете кода (само за четене) и събира пътища, команди за build и тест,
   решения от разговора;
4. пише самодостатъчен prompt по шаблона (`claude-backlog template`);
5. **ти го показва** - заглавие, приоритет, папка, цял prompt - и чака твоето
   OK. Ако има некомитнати промени, ги изброява и предлага да ги commit-не
   първо със съобщение, което ти одобряваш. Ако нова задача ще променя
   файлове, които друга неслята задача променя, предлага `--after`;
6. добавя я с `claude-backlog add` и ти връща id-то ѝ.

Skill-ът не добавя правилата за работа без надзор, `STATE.md` и т.н. -
claude-backlog ги добавя сам (виж по-долу).

### 5.2. Формата "New task" на дъската

Формата е на две стъпки: "What to do" и "Write the prompt".

**Стъпка 1.**

1. **Project folder** - пишеш, за да търсиш в проектите си, или въвеждаш
   път, започващ с `/` или `~`. Проектите се търсят в папките от настройката
   "Folders that hold your projects" (до две нива под тях).
2. **What should Claude do?** - няколко изречения със свои думи.
3. Приоритет (**High**, **Normal**, **Low**), дали да е в **Queue** или
   **On hold**, и по избор **Start from** (base branch), модел, effort,
   "5-hour windows per attempt" и "Attempts".
4. Натискаш **Add to the queue**.

Ако проектът има некомитнати промени, формата го казва и предлага **Commit
now**: показва променените файлове и ги commit-ва всичките в текущия branch
със съобщението, което напишеш (твоята git идентичност, твоите hooks;
файловете от `.gitignore` не влизат). Това е важно, защото задачата стартира
от последния commit.

**Какво се случва после (drafting).** Задачата се появява на дъската веднага,
със статус "drafting", а Claude пише пълния prompt на заден план, обикновено
за 10-20 секунди. Прави се един извик (по подразбиране Sonnet с ниско effort;
настройките "Model for writing prompts" и "Effort for writing prompts"), без
никакви инструменти и MCP сървъри. Преди това дъската сама събира "очертание"
на проекта без модел: списък на файловете, README, CLAUDE.md, командите за
build и тест и файловете, които съвпадат с описанието ти. Така prompt-ът има
реални пътища и истинските команди за тест на проекта.

**Въпроси с предположения.** Където описанието ти оставя нещо отворено,
prompt-ът прави предположение, а картата изброява въпроса заедно с това
предположение. Отговорът е по желание и ако го дадеш, се добавя към prompt-а
(в раздел "Answers from the user") без нов извик към Claude. Само когато
въпрос **блокира** задачата (например целите си противоречат), тя чака в
**On hold** за твой отговор (бутон **Answer**).

**Ако черновата не успее.** Картата остава в On hold със съобщение за грешка и
бутони **Retry the draft** и **Write it myself**.

**Write it myself.** Вместо да чакаш Claude, попълваш сам шаблона на prompt-а.
Редовете в ъглови скоби са подсказки - задача не може да бъде добавена,
докато такъв ред е останал непроменен.

### 5.3. Командният ред

```bash
claude-backlog add -p high "Migrate src/api to the v2 client; run the tests after each module"
claude-backlog add -C ~/projects/site task.md     # task файл, виж по-долу
echo "..." | claude-backlog add -C ~/projects/site -
```

Източникът (`source`) е самият prompt, `.md` файл със задача или `-` за
stdin. Опции на `add`:

| Опция | Значение |
|---|---|
| `-C`, `--project` | папка на проекта (по подразбиране текущата или `project` от файла) |
| `-t`, `--title` | заглавие |
| `-p`, `--priority` | `high`, `normal` или `low` |
| `--hold` | слага я on hold, не в queue |
| `--after ID` | започва след като задачата с това id е готова (от същия repository) |
| `-m`, `--model` | модел |
| `-e`, `--effort` | `low`, `medium`, `high`, `xhigh` или `max` |
| `-w`, `--max-windows` | колко 5-часови прозореца може да ползва един опит: число или `auto` |

`add` печата бележка, ако проектът има некомитнати промени, и въпреки това
добавя задачата.

Други полезни команди:

```bash
claude-backlog list              # опашката, какво тече, какво иска внимание
claude-backlog list -a           # плюс Done и Archived
claude-backlog list -C ~/projects/site   # неслетите задачи на repository-то
claude-backlog export ID         # печата задача като task файл
claude-backlog template          # печата шаблона на prompt-а
claude-backlog go                # същото като Run now
claude-backlog go --until 07:30  # не взема нови задачи след 07:30
claude-backlog stop              # спира след текущата задача
claude-backlog stop --now        # спира веднага (задачата се връща в queue)
claude-backlog report            # последния отчет
```

Командите `go` и `stop` говорят със service-а; ако той не работи, получаваш
съобщение, че service-ът не работи.

### Task файлове

Задача може да се опише и като Markdown файл с front matter:

```markdown
---
title: Migrate the API client to v2
project: ~/projects/acme-app
priority: high
model: opus
effort: high
max-windows: 3
---
Migrate every call in src/api/ from the v1 client to the v2 client. ...
```

Допълнителни полета: `status: hold`, `threshold`, `max-attempts`,
`base-branch`, `after` (id на задача, след която да започне). Без `project`,
`add` взема git root-а на папката на файла.

### Как се пише добър prompt

Най-добрият prompt е такъв, който би разбрал колега, който не е присъствал
на разговора и не може да ти се обади. Шаблонът (`claude-backlog template`,
променя се в Settings) следва това, в което съветите за автономни агенти
се съгласяват:

| Раздел | Какво да съдържа и защо |
|---|---|
| **Goal** | Какво трябва да е вярно накрая и защо е важно. Целта помага на Claude да вземе добри решения в непредвидени случаи. |
| **Context** | Откъде да започне: файлове, документи, съобщения за грешка, код като образец, как се пуска проектът. Реални пътища, не общи думи. |
| **Constraints** | Какво не бива да се променя и какво е извън обхвата: файлове, API, поведение, нови зависимости. |
| **Done when** | Наблюдаеми резултати, всеки с точната команда или стъпка, която го проверява. Без това Claude не знае кога да спре. |
| **Milestones** | За дълга задача: стъпки по ред, всяка проверима сама. За кратка задача се изтрива. |
| **When unsure** | Кои избори Claude може да прави сам, кои да остави за теб (те влизат в `SUMMARY.md`, вместо да бъдат налучквани) и какво да прави, ако нещо го блокира. |

Съвети:

- Назови проверката: "пусни `pytest` и `ruff check`, и двете трябва да минат"
  е по-добре от "увери се, че работи".
- Пиши за **една** цел на задача. Две независими работи са две задачи.
- Не обяснявай работата без надзор, `STATE.md`, commits и т.н. - това
  claude-backlog добавя сам.

### Правилата, които claude-backlog добавя към всеки prompt

Преди твоя текст се добавя фиксиран увод. Накратко казва на Claude да:

- работи без да пита; при неяснота да решава сам и да записва решението и
  причината в `STATE.md`;
- прочете `STATE.md` първо, ако съществува (там е записано какво са
  направили предишните сесии), и да го поддържа актуален - особено когато
  удари usage limit, за да може работата да продължи оттам;
- работи на малки стъпки, след всяка да пуска проверките и да commit-ва
  **само** в branch-а на задачата; да не прави push, да не сменя и не
  създава branches и да не прави merge;
- пипа файлове само в worktree-то и в папката на задачата;
- не отслабва и не заобикаля тестове и проверки, за да минат; ако тест или
  самата задача изглежда погрешна, да го каже в `SUMMARY.md`;
- накрая провери всеки критерий от "Done when" и напише `SUMMARY.md`:
  какво е направено, какви проверки са пуснати и с какъв резултат, какви
  проблеми остават и раздел "Decisions for me" (решения, оставени за теб).

`SUMMARY.md` се пише **само** когато задачата наистина е свършена: то е
сигналът, че е завършена. Това е причината задача, която приключи без
`SUMMARY.md`, да иска внимание.

Ако папката на проекта не е git repository, задачата работи директно в
нея, без branch, и правилата са по-прости (без commit, без push).

## 6. Изпълнение

### Как започва

Има два начина.

1. **Run now** на дъската или `claude-backlog go`. Използвай го, преди да
   тръгнеш. С `--until HH:MM` (или менюто до бутона) не се взема нова
   задача след зададения час.
2. **Автоматично, когато те няма** - ако е включено "Start when I am away".
   Service-ът проверява на всеки 30 секунди дали screensaver-ът е включен;
   когато е бил включен поне зададеното време (по подразбиране 15 минути,
   настройката `away_minutes`) и има какво да се изпълни, опашката тръгва
   с причина "away".

За откриване на screensaver се опитват по ред: Cinnamon screensaver, GNOME
screensaver, freedesktop screensaver (през D-Bus и `gdbus`) и накрая logind
(LockedHint/IdleHint, при който отсъствието се брои от първото засичане).
Ако нищо не отговаря на твоя десктоп, автоматичният старт не работи, но
Run now работи винаги.

### Какво става, когато се върнеш

Когато screensaver-ът се изключи, а изпълнението е било стартирано
автоматично, то спира. Колко рязко, зависи от настройката "When I come back
to a run that started by itself":

| Стойност (`on_return`) | Поведение |
|---|---|
| `stop` ("Stop it now") - по подразбиране | Текущата задача се спира веднага, връща се в queue и продължава от бележките си следващия път. |
| `finish` ("Let the current task finish") | Текущата задача се довършва, после опашката спира. |

Изпълнение, което си започнал ти с **Run now**, **не** се спира при
връщането ти. Ако натиснеш Run now, докато върви автоматично изпълнение, то
става "твое" и вече не спира при връщане.

### Ръчно спиране

- **Stop after this task** (`claude-backlog stop`) - довършва текущата
  задача и не взема нова.
- **Stop now** (`claude-backlog stop --now`) - праща SIGINT на nightshift;
  ако не приключи за 30 секунди, процесът се убива. Задачата се връща в
  queue и не се брои като опит.

Опашката спира и когато е празна, когато остане само чакащото други задачи
(зависимости), когато стигне седмичния лимит, когато не може да се прочете
ползването или когато мине часът `--until`.

### Една задача наведнъж и справедлив ред

Винаги работи най-много една задача. В рамките на едно изпълнение всяка
задача от queue получава ред, преди която и да е да получи втори. Така
задача, която е използвала прозорците си и се е върнала в queue, не заема
мястото на другите.

### Git worktree и branch

За проект в git repository, преди първия опит claude-backlog:

1. определя началната точка - текущия commit на base branch-а (или branch-а
   на задачата, след която е зададено да започне, ако не е слят);
2. създава branch `backlog/<task>` и отделен **worktree** в
   `~/.local/share/claude-backlog/worktrees/<task>`;
3. пуска Claude в това worktree, с твоята git идентичност.

Така твоят работен екземпляр никога не се пипа. След всеки опит, ако в
worktree-то са останали некомитнати промени, те се commit-ват автоматично със
съобщение "backlog: commit what attempt N left uncommitted".

### systemd-inhibit

Докато опашката върви, service-ът държи `systemd-inhibit` заключване срещу
sleep и idle. Така компютърът не заспива насред работа. (Ако `systemd-inhibit`
липсва, дъската го показва.) Заключването не помага срещу затваряне на капака
на лаптопа - то суспендира компютъра въпреки всичко, затова го оставяй
отворен. Дъската предупреждава (за Cinnamon и GNOME), ако компютърът ще
заспи преди да мине времето за "away".

### Чакане на 5-часовите лимити и седмичния лимит

Тук работи claude-nightshift:

- Всеки опит може да ползва до **2 прозореца** по 5 часа по подразбиране
  (`max_windows`; число или `auto`). Когато Claude удари 5-часов usage limit,
  nightshift изчаква нулирането и възобновява задачата.
- Преди всяка нова Claude сесия nightshift проверява седмичното ползване.
  Ако е на или над зададения дял (**Stop when weekly usage reaches**,
  по подразбиране **50%**), нова сесия не започва и опашката спира. Всяка
  задача може да има собствен праг (`threshold`).
- Ако опит не е довършил задачата в позволените прозорци, задачата се връща
  на мястото си в queue и се опитва пак - до **3 опита** по подразбиране
  (`max_attempts`). След това отива в **Needs attention**.

Как claude-backlog тълкува exit code-а на nightshift:

| Exit code | Значение | Резултат |
|---|---|---|
| 0 и има `SUMMARY.md` | свършено | **Done** |
| 0 без `SUMMARY.md` | Claude е свършил без да напише резюме | **Needs attention** |
| 1 | неуспех (грешка на Claude или изчерпани повторения) | **Needs attention** |
| 2 | nightshift отхвърлил аргументите си | **Needs attention** |
| 3 | достигнат седмичен лимит | задачата в queue, опашката спира |
| 4 | прозорците на опита са изчерпани | в queue за нов опит (или Needs attention след последния) |
| 5 | седмичното ползване не може да се прочете | в queue, опашката спира |
| 130 | прекъснато (Stop now, връщане) | в queue, без да се брои опит |
| друго | неочакван край | **Needs attention** |

Ако service-ът умре по време на изпълнение, при следващия старт задачата,
която е била "running", се връща в queue с бележка "the service stopped while
this task was running".

### STATE.md и SUMMARY.md като бележки на задачата

Папката на задачата (`~/.local/share/claude-backlog/tasks/<id>/`) съдържа:

| Файл | За какво служи |
|---|---|
| `prompt.md` | пълният prompt на последния опит (уводът + твоят текст) |
| `STATE.md` | бележките на Claude за напредъка и взетите решения. Защо: контекстът на Claude се свива и задачата се възобновява след лимити, а новата сесия няма друга памет. |
| `SUMMARY.md` | крайният резултат: какво е направено, проверки, отворени проблеми и "Decisions for me". Появата му означава "свършено". |
| `logs/` | логът на всеки опит |
| `nightshift-status.md` | статусът на nightshift |

Ако задача се пуска отново (**Run again**), старият `SUMMARY.md` се
преименува, за да не бъде взет за нов резултат.

### Отчети и известия

Всяко спиране на опашката записва отчет (`claude-backlog report` печата
последния; файловете са в `reports/`): кога и защо е започнало и спряло,
таблица със задачите (резултат, exit code, време, брой commits, лог),
началото на всеки `SUMMARY.md` и какво още е в queue. Показва се и
десктоп известие (чрез `notify-send`, ако го има).

## 7. Преглед на резултата и merge

### Преглед

Завършените задачи се появяват в **Done** с означение "new", докато ги
отвориш. На картата виждаш и броя commits, а ако `SUMMARY.md` има раздел
"Decisions for me", и колко решения чакат теб.

В панела на задачата:

1. **Overview** - прочети `SUMMARY.md` първо. Той казва какво е направено,
   какво е проверено и какво е оставено на теб.
2. **Changes** - прегледай diff-а.
3. Ако нещо не ти харесва, промени prompt-а и натисни **Run again**, или
   работи по branch-а на ръка.

### Merge

Панелът показва командата за merge, например:

```bash
git -C ~/projects/site merge backlog/migrate-the-api-client-to-v2-1
```

Сам решаваш дали да я изпълниш, да направиш cherry-pick, да поискаш промени
или да изтриеш branch-а (**Delete the branch**). След merge картата се
означава "merged". Ако не си доволен, **Archive** маха worktree-то и запазва
branch-а, за да можеш да се върнеш към него.

Ако командата `git merge` даде конфликт, виж по-долу.

### Припокриващи се задачи и конфликти

Branch-ът на всяка задача започва от base branch-а такъв, какъвто е в
момента на старта. Затова две задачи на един проект **не виждат** работата
една на друга, освен ако не си слял първата междувременно. Така всеки
branch е независим и можеш да слееш или откажеш всеки отделно. Цената е, че
двата може да променят едни и същи файлове и да се стигне до конфликт.

Какво ти помага:

- **Start from** / **Start after** / `add --after ID`. Когато една задача
  надгражда друга, задай да започне "след" нея: тя чака в queue, докато
  другата е готова, после започва от нейния branch, така че merge-ът ѝ
  донася и двете.
- **Предупреждение преди изпълнение.** Ако prompt-ът на още неизпълнена
  задача назовава файлове, които друга неслята задача променя, картата
  показва "may change the same files as ..." с бутон **Start after it**.
  Формата "New task" също изброява неслетите задачи на проекта, а `/backlog`
  ги проверява с `claude-backlog list -C <папка>`.
- **Проверка за конфликти.** Дъската проверява всеки завършен, неслят
  branch спрямо base branch-а и спрямо другите завършени branches на същия
  repository с `git merge-tree` (който не пипа файлове; нужен е git 2.38 или
  по-нов). Картата с конфликт го показва ("merge conflict with ..."), а
  панелът изброява файловете. Branch, съдържащ се изцяло в друг завършен
  branch, се показва като част от него.
- **Claude разрешава конфликта.** Конфликтът не е провалена задача и не
  е нужно да го решаваш на ръка. **Update with Claude** (конфликт с base
  branch-а) или **Combine with Claude** (конфликт с branch на друга задача)
  добавя в queue нова задача, която започва от branch-а на твоята,
  слива в него другия branch, разрешава конфликтите и пуска проверките. Ти
  после преглеждаш и сливаш branch-а на тази последваща задача, който
  донася и оригиналната. (Само тази задача има право да направи точно този
  един merge - в prompt-а ѝ е изрично позволен.)

Алтернатива е да слееш единия branch първо и да решиш остатъка на ръка.

## 8. Достъп от телефон през Tailscale

Целта е да виждаш какво тече и да променяш какво ще прави Claude после,
докато си навън. Достъпът минава само през твоята собствена Tailscale мрежа.

1. Инсталирай Tailscale на компютъра и на телефона, влез в един и същ
   акаунт и го стартирай (`tailscale up`).
2. Изпълни:

   ```bash
   claude-backlog install --phone
   ```

   Това пуска еднократно
   `tailscale serve --bg --https=443 http://127.0.0.1:8766`. Настройката
   оцелява след рестарт. Ако Serve или HTTPS сертификатите не са включени
   за tailnet-а ти, командата изписва адрес, на който да ги включиш, и я
   пускаш пак. Ако Tailscale иска права, виж съобщението (напр. еднократно
   `sudo tailscale set --operator=$USER`).
3. На дъската отвори **Settings**, въведи своя Tailscale login (**Your
   Tailscale login**, настройката `tailscale_login`) и сканирай показания
   QR код с телефона. Добави страницата на началния екран.

Безопасност: пускането на задачи е пускане на команди с твоите права, затова
в телефонния достъп влиза само зададеният Tailscale login. Никога не
отваряй дъската през Tailscale Funnel или с отворен порт. За да изключиш
телефонния достъп: `tailscale serve --https=443 off`.

## 9. Настройки (Settings)

Бутонът **Settings** на дъската отваря прозорец. Имената на настройките по-долу
са тези от кода; в скоби е етикетът в интерфейса.

| Настройка | По подразбиране | Значение |
|---|---|---|
| `threshold` (Stop when weekly usage reaches) | 50 | Дял от седмичния лимит (1-100), при който не се започват нови сесии. Подава се на nightshift за всяка задача. |
| `away_enabled` (Start the queue when I am away) | включено | Дали опашката тръгва сама при отсъствие. |
| `away_minutes` (Away means the screensaver has been on for) | 15 | Минути с включен screensaver, преди да се счита, че те няма. |
| `on_return` (When I come back to a run that started by itself) | `stop` | `stop` - спира веднага; `finish` - довършва текущата задача. |
| `model` (Model) | празно | Модел за задачите; празно е стойността по подразбиране на Claude. |
| `effort` (Effort) | празно | `low`, `medium`, `high`, `xhigh`, `max`; празно е по подразбиране на Claude. |
| `max_windows` (5-hour windows per attempt) | `2` | Колко 5-часови прозореца може да ползва един опит: число или `auto`. |
| `max_attempts` (Attempts) | 3 | Колко пъти се опитва недовършена задача, преди да иска внимание. |
| `draft_model` (Model for writing prompts) | `sonnet` | Модел, който пише prompt-а от краткото описание (`sonnet`, `haiku`, `opus` или по подразбиране на Claude Code). Отделен от `model`, който е само за изпълнението. |
| `draft_effort` (Effort for writing prompts) | `low` | Effort за писането на prompt-а. |
| `project_roots` (Folders that hold your projects) | домашната папка | Папки (по една на ред), чиито подпапки формата "New task" предлага като проекти. |
| `prompt_template` (Prompt template for new tasks) | шаблонът с Goal, Context, Constraints, Done when, Milestones, When unsure | Какво се слага в полето за prompt. Има бутон **Restore the default template**. |
| `tailscale_login` (Your Tailscale login) | празно | Логинът, на който е разрешен телефонният достъп. |
| `port` | 8765 | Порт на дъската; телефонният е следващият. Няма поле в прозореца - използва се от `serve --port` (виж `claude-backlog serve --help`). |

Модел, effort, прозорци и опити могат да се задават и поотделно за всяка
задача (в формата, в панела, в task файл или с опциите на `add`); празната
стойност означава "от Settings".

Прагът може да се промени и с клик върху маркера на лентата за ползване.

## 10. Често срещани проблеми

**Дъската не се отваря / `go` или `stop` казват, че service-ът не работи.**
Командите `go`, `stop` и `open` разчитат на работещ service. Провери:

```bash
systemctl --user status claude-backlog
journalctl --user -u claude-backlog
```

Ако не е инсталиран, пусни `claude-backlog install`. За бърз опит, без
service: `claude-backlog serve`. Ако си сменил порта, `open` и CLI използват
порта от настройките.

**Опашката не върви, след като съм се разлогвал.** Най-вероятно linger е
изключен и user service-ът е спрял. Включи го с `loginctl enable-linger`.

**Опашката не тръгва сама, докато ме няма.**

- Провери дали "Start when I am away" е включено и има задачи в Queue
  (не On hold).
- Прозорецът Settings показва кой детектор за screensaver е намерен. Ако
  няма такъв, автоматичният старт не е възможен - ползвай Run now.
- Компютърът може да заспива преди да изтекат минутите за отсъствие
  (дъската предупреждава за Cinnamon и GNOME). Увеличи времето до
  заспиване или намали `away_minutes`.
- Капакът на лаптопа е затворен - суспендира независимо от `systemd-inhibit`.

**Задача в Needs attention.** Картата носи бележка за причината. Най-честите:

| Бележка | Какво значи | Какво да направиш |
|---|---|---|
| "Claude finished without writing SUMMARY.md" | Claude е приключил, без да запише резюме. Често значи, че не е довършил или prompt-ът не е бил достатъчно ясен. | Прочети лога и `STATE.md`; поправи prompt-а; **Run again**. |
| "nightshift failed (exit 1): see the log" | Грешка на Claude или изчерпани повторения. | Виж лога в таб **Log**. |
| "not finished after N attempt(s)" | Всички позволени опити са използвани. | Прочети `STATE.md`, раздели задачата на по-малки, увеличи `max_windows`/`max_attempts` и **Run again**. |
| "could not prepare the git worktree: ..." | Не може да се създаде worktree (напр. проблем с repository-то). | Прочети съобщението; поправи repository-то; **Run again**. |

**Опашката спря с "weekly usage could not be read".** nightshift не успя да
прочете ползването ти (изход 5). Задачата остава в queue. Провери, че Claude
Code е влязъл и че `claude-nightshift` е достъпен (променливата
`CLAUDE_BACKLOG_NIGHTSHIFT` може да промени как се стартира).

**Опашката спря с "weekly limit reached".** Това е нормално: достигнат е
зададеният дял. Повиши `threshold`, ако искаш да продължи, или изчакай
следващата седмица.

**Чернова остана on hold след usage limit.** Ако самият usage limit на
Claude е спрял писането на prompt-а, картата показва съобщение и час, в
който Claude ще го напише отново сам: минута след времето за нулиране от
съобщението на Claude, или след половин час, ако то не го посочва. Не е
нужно да правиш нищо; можеш да натиснеш **Retry the draft** и по-рано или
да използваш **Write it myself**.

**Конфликт при merge.** Виж [Припокриващи се задачи и
конфликти](#припокриващи-се-задачи-и-конфликти) - **Update with Claude** /
**Combine with Claude**.

**Задачата не вижда мои скорошни промени.** Тя започва от последния
commit. Commit-ни промените преди да добавиш задачата (формата предлага
**Commit now**).

**Изтрих задача, но branch-ът остана.** Нормално е: **Delete** и **Archive**
запазват branch-а. Изтрий го с **Delete the branch** или с `git branch -D`.

## 11. Речник

| Термин | Обяснение |
|---|---|
| backlog | Списък с работа, която чака да бъде свършена; тук - опашката от задачи. |
| queue | Опашка: подредените по приоритет задачи, които ще се изпълнят. |
| prompt | Текстът с инструкции, който Claude получава за задачата. |
| drafting | Състояние, в което Claude пише пълния prompt от краткото ти описание. |
| worktree | Допълнителна работна директория на същия git repository, с отделен branch. Позволява задачата да работи, без да пипа твоя екземпляр. |
| branch | Клон в git; всяка задача има `backlog/<task>`. |
| commit | Запис на промени в git. |
| diff | Разликата между две версии на кода. |
| merge | Сливане на промените на един branch в друг. |
| base branch | Branch, от който започва задачата (обикновено текущият). |
| usage limit | Лимит на ползването на Claude: 5-часов прозорец и седмичен дял. |
| usage window | 5-часов прозорец на ползване, в който Claude има определен бюджет. |
| threshold | Прагът на седмичното ползване, при който опашката спира. |
| attempt | Един опит да се изпълни задачата (може да обхваща няколко прозореца). |
| STATE.md | Бележките на Claude за напредъка, нужни за възобновяване. |
| SUMMARY.md | Крайният отчет на Claude; появата му означава "свършено". |
| claude-nightshift | Инструмент, който изпълнява една задача през usage windows в рамките на седмичен бюджет. |
| service | Фонов процес, който държи дъската и изпълнява опашката. |
| systemd | Системата за управление на услугите в Linux. |
| user service | Service на systemd, който работи под твоя потребител, не като root. |
| linger | Настройка на systemd (`loginctl enable-linger`), с която user service-ите продължават да работят и след log out. |
| systemd-inhibit | Заключване, което пречи на компютъра да заспи, докато опашката работи. |
| screensaver | Скрийнсейвърът/заключеният екран; използва се, за да се познае, че те няма. |
| skill | Разширение на Claude Code; `/backlog` е skill. |
| hook | Скрипт на git (или на Claude Code), който се изпълнява при определено събитие, напр. преди commit. |
| exit code | Число, с което процес казва как е приключил; nightshift така съобщава защо е спрял. |
| Tailscale | Частна мрежа между твоите устройства; ползва се за достъп от телефон. |
| Funnel | Функция на Tailscale за публично излагане на услуга в интернет; за дъската никога не се ползва. |
